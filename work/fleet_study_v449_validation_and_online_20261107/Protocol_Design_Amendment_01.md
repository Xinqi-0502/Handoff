# Protocol design amendment 01: prospective nine-method comparison

Status: PREPARATION ONLY. No V449 correctness solver, cost benchmark or main benchmark has been run by this preparation.

The parent relayed a new user requirement: identify the best currently available combination that includes the joint bound, considering early useful solution quality as well as proof/completion time. Before any V449 outcome, the seven-method draft was therefore expanded to nine prespecified methods by adding RADIUS_PAIR_AWA and RADIUS_PAIR_AWA_GATED. Both are existing frozen V448 internal policies with basis=radius; only the V449 driver gives them explicit public names.

The six seven-method draft source files are preserved in snapshots/seven_arm_pre_design_amendment_01. The 100-mother/400-scenario main input was structurally generated before this method amendment, with no solver evaluation or outcome filtering. Its geometry, seeds, cargo, services and treatments are unchanged. The final numerical-source manifest is created after this amendment. Thus this is a prospective user-directed design change, not a reaction to new confirmation outcomes.

Final main design: nine methods, all three serial balanced repeats, same one-second solver budget, 100 new independent mothers and 400 related scenarios: 10,800 calls. There is no additional tuned weight or new bound formula. Existing w=2 remains fixed. RADIUS_AWA uses the radius base; RADIUS_PAIR_AWA uses the full radius-based PAIR value for weighted ordering; RADIUS_PAIR_AWA_GATED retains weighted radius ordering and uses the joint condition only for the incumbent-dependent prune check.

The full existing 32-scenario cost input remains archived. To limit the cost pilot before the main launch, use only the first prespecified mother at each size, all four paired variants: input ranges 0:4, 8:12, 16:20 and 24:28. This is 4 independent cost mothers / 16 related scenarios, nine methods once each, 144 calls. The unused second mother at each size is reserved, not removed by an outcome rule. One cost observation is not a repeated speed comparison and will not be pooled with main results. It may determine operational feasibility and whether a run should stop; it may not choose winning seeds/methods or silently alter the main budget.

The comparison will report literal 100/500/1,000 ms quality, first attainment of exact/5%/10% relative-to-duration targets when an exact oracle is known, certificate coverage, and paired proof/completion cost. The best observed policy may differ by target. A best policy identified from this comparison is an observed winner within the prespecified set and model, not an independently confirmed winner selected in advance. All nine methods and unfavorable results remain reported. No new policy will be added or tuned from main outcomes.
