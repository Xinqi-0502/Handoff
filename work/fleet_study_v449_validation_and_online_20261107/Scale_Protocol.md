# V449 frozen scale-validation protocol

Status: STATIC PREPARATION. This file does not authorize a numerical launch. Source review, the complete adapter micro gate and the parent's monitored-launch decision are required. Online/SUMO work in the same V449 parent directory is a separate evidence line; this scale protocol does not execute SUMO.

## Inputs and units

Main: exactly 100 new independent mother networks, m=6/8/10/12 with 25 mothers each. Each mother has Q=L or ceil(1.25L), crossed with signal off/on, yielding 400 related scenarios. Main seeds are 94490000+1000*m+i, i=1..25. The frozen V447 distributions are reused: directed random 2D graph, deterministic FIFO road calendars, positive unequal old weights with L in 120/160/200, positive services, wa=.6L, wb=.8L. Capacity and signal pairs change only their declared model axis. No outcome filtering is permitted.

The separate cost seed namespace is 94480000+1000*m+i. Thirty-two scenarios (i=1,2) were generated and retained. The prespecified operational cost check uses i=1 only at each m, all four variants: 16 scenarios / 4 mothers, one observation per method. Its ranges in the retained input are 0:4,8:12,16:20,24:28. Cost and main seeds are disjoint and were checked against V447 micro/pilot/main and V448 pilot seed sets. These checks read old inputs, not performance outcomes for seed selection.

The model remains one fixed receiver and hub, two atomic incoming batches a then b, 0<wa<wb<=Q and wa+wb>Q, positive services, load-independent FIFO movement with waiting, objective second-handoff completion H2. There is no global fleet assignment, arbitrary number of new batches, demand calibration, SUMO execution or city-level benefit claim.

All main methods receive three repeats. There are 10,800 main calls. Original V448 numerical solver/reference files are imported with exact pinned hashes and never edited. Existing public aliases are reused; the two new AWA names map explicitly to already implemented policies. DP is not presented as a reproduction of a named published freight system. AWA and Lazy are published search-policy adaptations within this common restricted model, not external end-to-end routing-system reproductions. No 'all current best freight methods beaten' claim is supported.

Rotate method order by (repeats*schedule_case_index+repeat) mod 9. Main uses the global case index. Cost uses the continuous ordinal of the 16 selected cases. Each method's global position counts differ by at most one; within a single case three repeats cannot exhaust all nine positions. Calls are serial, with fresh context/caches and common garbage collection outside each measured call. There is no cross-call heuristic or oracle cache sharing.

## DP initialization, algorithm and independence

DP_ADAPTER retains the frozen reference DP's state (phase,remaining-old-mask,a-delivered,position), earliest-time labels, increasing topological rank, sorted-bucket traversal and handwritten actions. It uses no proposed bound and no incumbent pruning. Its independent full-vector Dijkstra closure differs from the production scalar-query closure; both implementations pay their own real costs.

At entry, start the clock before validation, network construction and mask-weight/DP storage setup. Recreate the same common feasible greedy plan using the DP closure: repeatedly choose minimum (old service-completion time,item id,node), deliver all old items, receive/deliver a, then receive b. No exact G evaluation is performed. The micro gate requires the plan and H2 to equal the common production initializer exactly. Greedy closure caches may be reused within that same DP call, just as production reuses its own initialization cache; no preparation is free.

The greedy plan is only an incumbent fallback, not a pruning rule. Strict improvements generated by DP reconstruct a feasible plan and record their real timestamp immediately. The DP's first internally discovered terminal is also recorded separately. Setup, initial planning, queries, path reconstruction, trace recording and certificate/statistic construction are included in elapsed time. The reference 15-second oracle's solution, plan, values and caches never enter the measured DP or other solves.

DP's soft cutoff is checked between labels/queries and inside Dijkstra after the common initializer. A partial final parent is separately counted and not included in completed expansions. Production policies retain their frozen full-expansion-boundary checks. This is a stopping-granularity difference, disclosed rather than hidden. Primary quality is reconstructed from timestamps for every method, and late improvement/proof gets no deadline credit. DP expansion counts and search-label counts are work diagnostics, not CPU-equivalent budgets across algorithms.

Only genuinely completed structural DP traversal certifies optimality. Interrupted DP returns the feasible incumbent and conservative lower bound t0; rank progress is not a completion-time bound. No incomplete-frontier certificate is invented. The nonzero mandatory services ensure a partial DP's t0 bound cannot accidentally claim equality with H2.

The validation oracle is the frozen reference DP running from scratch with up to 15 seconds outside measured solves. It shares recurrence/network code with DP_ADAPTER; therefore this is NOT independent algorithmic validation of DP_ADAPTER. Independent correctness evidence for DP consists of separate full timed-prefix exhaustive enumeration on small cases and the frozen production-reference action replay on every DP improvement plan. The oracle remains independent of the six-plus-two proposed-bound production policies, but not the DP comparator. Unknown exact oracle targets remain unknown; feasible replay alone is not an optimality proof.

## Timing, quality and failure accounting

All methods have a one-second soft budget and a cooperative 15-second safety watchdog. No uncensored optimum target is supplied to the solver. Oracle/replay and data serialization are outside measured algorithm time. Setup+initial+search partitions elapsed. Root-bound time is nested in search and is not added again. Existing V448 numerical accounting is retained.

Record complete raw incumbent traces, final H2/plan, phase expansions, DP partial expansion, final valid bound/gap, setup/initial/search/root/elapsed times, overrun and all outcomes. Literal H2 at 100/500/1,000 ms uses only trace entries at or before the cutoff. On-time proof requires final certification and elapsed<=1 second. End-of-soft-run values stay separate. First exact/5%/10% targets are computed only afterward using target=optimum+fraction*(optimum-t0). Oracle uncertainty and zero denominators are not assigned zero regret.

HARD_TIMEOUT keeps external call duration and missing incumbent/component statistics rather than invented values. Verification or source-identity failure is fatal, saves REJECTED_RESULTS/FAILURE and blocks following jobs. Soft-budget uncertified results are preserved. PROCESS_COMPLETE PASS means complete accounting, not that every method solved every instance. All retries use fresh folders and explicit selection; never overwrite or remove an unfavorable case.

No native RAM or tracemalloc experiment is part of this protocol. Cache/frontier/DP label counts are not bytes and cannot establish actual-memory reductions. Detailed profiling is off for the comparative measurements.

## Gate and serial blocks

The already completed V448 full micro gate remains required for its unchanged numerical core. The new adapter gate uses all 24 frozen V447 micro scenarios (m3/4/5, six mothers), in six fresh batches of at most four cases. Per case: separate full timed-prefix exhaustive optimum; old structural DP agreement; all nine methods unlimited to the same optimum/common initializer; every improvement plan replayed; DP caps 0.001/1/1,000 ms checked for timer/trace/certificate/literal semantics. There are 12 solution checks per micro case, including three capped DP calls. Reusing these for correctness does not make them independent performance samples.

After all 24 PASS, assemble a source-bound gate from the explicit selected check directories. The measurement driver rechecks the gate and sources before any oracle or solve. Files and evidence hashes are bound; changing source invalidates this gate.

Prepared cost schedule: four jobs, each one mother/four paired scenarios, nine methods once, 36 calls/job and 144 calls overall. The parent can inspect each complete scale block before permitting the next. No main run is automatic.

Prepared main schedule: 52 jobs, each confined to one scale and complete mothers. Most jobs contain two mothers/eight scenarios/216 calls; each scale's final job contains one mother/four scenarios/108 calls. All 400 scenarios remain scheduled. Any thermal or resource stop preserves partial data and blocks dependent jobs; the existing monitored E workspace policy (60 C stop, stop on monitor failure) applies.
